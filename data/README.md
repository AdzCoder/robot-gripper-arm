# Test captures

Raw serial dumps from the 2023 build, exactly as the monitor emitted them: captures
rather than curated datasets, so they carry no header rows.

## `PID_data.csv`

687 rows, three columns, no header:

| Column | Meaning | Units |
|---|---|---|
| 1 | `avgCurrent`, the 35-sample moving average of INA219 motor current | mA |
| 2 | `setPoint`, constant throughout | mA |
| 3 | `output`, the PWM value written to the motor driver | 0-255 |

One closing cycle. The output starts at 0, jumps to 70 as `startTightening()` sets it
to `MOTOR_SPEED`, then climbs under control to a peak of 195.88, so the 255 clamp is
never reached. A step back to exactly 70.00 partway through is a second entry into
`startTightening()`.

**This capture was taken at KP = 0.03, not the 0.02 in the firmware.** The step in the
output divided by the error is exactly 0.030000 at the median and at both the 10th and
90th percentiles across all 640 changing samples. The same result shows that KI and KD
were genuinely zero for this run: any integral term would make the step depend on
accumulated error, and any derivative term would add a component in error differences,
and either would destroy the exact proportionality that is present.

`printDebugInfo()` emits labelled text rather than this bare three-column format, so the
file cannot be regenerated by building and running the repository as it stands.
